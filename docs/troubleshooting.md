# 常见问题

## 安装成功，但不知道怎样使用

在下一轮对话中显式输入 `$painted-animation` 或 `$kinetic-reel`，同时说明视频内容、时长、比例和素材。技能提供的是创作流程与代码工具，不是一次调用就返回视频的云端接口。

已有同名技能时，安装器会停止。先比较新旧目录并保存自己的修改；不要把上游原版直接覆盖到有迁移修复的版本上。

## Node 版本不对

`new_project.sh --check` 要求 Node ≥22.12。查看 `node -v` 和 `command -v node`，使用机器已有的合适版本或安装兼容版本。只为本次命令设置 PATH，不必改变其他项目的默认环境。

## 找不到 Chrome 或 ffmpeg

Chrome 通过 `CHROME_PATH` 或渲染命令的 `--chrome=...` 指定。确保 `ffmpeg`、`ffprobe` 在 PATH 中，并实际运行 `ffmpeg -version`。初始化检查会在写入项目前停止；这种情况不能报告项目已可渲染。

## 画面太单一

先查重复的是地点、景别、视角还是动作。让同一段情绪通过不同事件展开，比如“分别”可以表现为拉远距离、巴士离开、车窗内看向窗外；细节应服务当前事件。可复用 [丰富画面的迭代提示词](../examples/qingtian/prompts.md)。

## 雨丝、栏杆或水纹不见了

本版 `inkLine` 对只有两个点的笔画使用直线样条路径。复制旧模板时，确认带上新版 `src/core.js`。不要通过无限增粗笔画掩盖没有实际绘出的路径。

## 混合图片与笔画时颜色异常

确认 `studio.html` 在 p5.brush 后加载 `src/brush-compat.js`。它修复 p5 的着色器缓存与实际 GL 程序不一致的问题。仍有异常时检查局部绘制顺序、遮挡与状态，并抽取问题前后的连续帧；该兼容层不是所有跳色问题的通用保证。

## 修改了代码，编码结果还是旧画面

重新执行 `--frames`。画面输入变化后，缓存签名会失效；只渲染局部区间不会补齐整片。音频单独变化可以重编码；远程字体或手动修改 `node_modules` 不在完整缓存追踪范围，需 `--frames --force` 重画全片。

## 歌词对不上或高亮不准

先确认音源版本和截取起点，再修行级时间，最后检查逐字高亮。`beat_grid.py` 估计节拍，不识别歌词。案例中保存的词级时间是模型估计，换歌需要重新对齐。也可以先采用经过核对的整行字幕。

## 中文缺字、字体不同

检查实际字体是否加载。通用模板含网络字体，网络不可用时需把字体及许可保存到项目，并改为本地 `@font-face`。案例的字符子集只覆盖原有字幕；新增标题或替换歌词后要补齐字符。

## 渲染太慢

先渲染少量有代表性的镜头，测量本机速度，再决定并发数。复杂静态布景可以预绘制；人物、风雨、道具与镜头保持动态。图片纹理应在最终纸纹和字幕之前合成。GPU 不可用时可以尝试模板的 `--soft-gl`，速度会不同。

## 改竖屏可以直接裁切吗

两套模板默认横屏。改成 9:16 后，需要重新安排人物关系、标题、HUD、镜头与字幕区域，并逐镜头检查；直接居中裁切可能丢失关系和关键动作。

## 自动检查通过就代表成片没有问题吗

完整解码只能证明文件可解码；参数与黑场检测只覆盖对应技术指标。抽帧能检查构图，连续帧能检查局部动作，完整观看与试听才能检查全程体验。交付时分别说明做过哪些检查。
